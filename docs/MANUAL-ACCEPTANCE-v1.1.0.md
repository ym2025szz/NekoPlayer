## 本轮真实媒体与 GUI 记录

本轮真实游客联网验证在独立临时数据目录执行，不登录或读取账号凭据。网易云、QQ 与酷我搜索各返回 5 条结果，歌词均可解析。各平台首曲的试听或权限限制仍保留在报告；媒体验证只选取可解析的独立候选，不能把候选成功扩展到整个搜索列表。

| 平台 | 媒体歌曲标识 | 候选来源 | 探测时长 s | 起始 2 s PCM 字节 | 末段 Seek 请求 s | Seek 后 2 s PCM 字节 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 网易云 | `1357374736` | 搜索结果 | 239.56 | 64000 | 236.56 | 64000 |
| QQ 音乐 | `000C9FCy4HUcTW` | 显式稳定标识 | 201.62 | 64000 | 198.62 | 64000 |
| 酷我 | `19528080` | 搜索结果 | 366.97 | 64000 | 363.97 | 64000 |

三项 probe、初始 decode 和偏移 seek decode 进程均退出 0。测试使用 FFprobe 与有界 FFmpeg PCM 管道，没有打开音频设备；`FullPlaybackVerified` 为 false。报告不记录原始媒体 URL、签名、Cookie、令牌或请求头。

最新报告酷狗搜索返回 403/guest-auth-required，汽水返回 429/rate-limited；歌词和媒体因无搜索候选未尝试。验证器退出 1 表示仍有受限平台，不能把该退出码解释为三个已验证媒体样例失败，也不能把限制平台记为可播放。

实际 GUI 使用独立 `NEKOPLAYER_DATA_ROOT`、静音与 1280×760 窗口：已观察中文搜索的网易云、QQ、酷我结果逐组出现，封面为真实平台封面，首个可用组自动选中；网易云偶发 429 时对应错误清楚可见。QQ“夜雨 / 陈滢竹”通过正式播放器进入设备 Playing，播放位置到 123 秒；暂停后提交 180 秒定位，状态仍为 Paused。退出并重启后恢复队列的稳定在线元数据及 180 秒位置，没有启动解码或自动发声。这些观察不验证声音质量或所有播放操作。

860×600 已确认首页渲染及更多播放操作入口可达；在线搜索页面在该尺寸、100%/150%/200% DPI 全部矩阵、人工听感、干净 Windows 虚拟机和离线首次 GUI 仍保留待验收。搜索历史提供选用、单条删除和清空，最近播放提供单条移除、撤销和确认后清空，删除作用范围分别为对应历史记录。

## 发布副本、无全局 Node 与中文空格目录

1. 先完成 `setup-ffmpeg.ps1`、`setup-music-gateway.ps1` 与 `publish-win-x64.ps1`。发布包自带 .NET、FFmpeg、Node 和网关依赖。
2. 把完整 `artifacts/publish/win-x64` 复制到 `artifacts/acceptance/猫娘 播放器 v1.1.0`。必须复制整个目录，不能只复制 EXE。
3. 在一个新的 PowerShell 会话运行下面命令。此会话的 PATH 只留系统目录，不改变持久系统设置；退出该会话即可恢复环境。

```powershell
$packageDirectory = Join-Path (Get-Location) 'artifacts\acceptance\猫娘 播放器 v1.1.0'
$env:NEKOPLAYER_DATA_ROOT = Join-Path (Get-Location) 'artifacts\acceptance\独立 用户数据 v1.1.0'
$env:PATH = "$env:SystemRoot\System32;$env:SystemRoot"
Set-Location -LiteralPath $packageDirectory
& '.\music-gateway\node\node.exe' --version
Start-Process -FilePath (Join-Path $packageDirectory 'NekoPlayer.exe') -WorkingDirectory $packageDirectory
```

预期：Node 输出 `v24.21.0`；应用正常打开；设置显示 `v1.1.0`；默认封面和图标显示正常；本地导入与播放可用；选择在线入口时应用自己启动随包 Node，用户不用运行 npm 或额外启动网关。实际网络可用时，在线请求通过同包运行时完成。关闭应用后随包 Node 不残留。

4. 重启应用时把工作目录改成其他目录，仍用绝对 EXE 路径启动。预期：应用仍按程序与已识别源码路径查找资源，不依赖当前工作目录。
5. 在未安装 Node/.NET 的干净 Windows 10/11 x64 机器或虚拟机重复整个步骤。系统 PATH 裁剪只能检查本会话不依赖全局命令，不能代替干净机器验收。

## 离线初始启动与 Node 故障

1. 使用上方独立发布副本与独立数据根，在虚拟机中断开网络后首次启动。无需下载 Node/npm；应用打开、显示空本地曲库、导入本地文件和本地播放应可用。在线请求失败时有可理解状态，导航和播放器仍响应。
2. 网络恢复后重试在线搜索，确认不是持续保存一个离线失败结果。
3. 仅在验收副本中，把 `music-gateway/node/node.exe` 临时改名为 `node.exe.disabled`。启动应用并导入、播放一首本地歌曲；在线入口应报告运行时不可用，本地功能可继续使用。退出应用后还原文件名，再重试在线功能。
4. 仅在副本中临时改名 `music-gateway/server.mjs`，重复本地可用与在线失败检查；随后还原。不要对正式发布目录或用户数据执行此步骤。
5. 网关正在请求时关闭应用；等待数秒后检查进程列表，不应残留由此应用启动的 `node.exe`。检查实例时以完整路径和进程关系判断，不应结束其他应用的 Node。

## 在线搜索与播放

- 分别在网易云、QQ、酷我、酷狗和汽水搜索普通关键词；记录真实响应与对应状态。一个平台超时或失败时，其他平台已有结果应仍可见。
- 快速连续改变关键词并重复提交，取消与较旧请求不得覆盖最后一次搜索；空关键词、零结果、限流、权限不足及超时必须有明确状态。
- 搜索历史分别检查选用、单条删除和清空；删除单条后其余历史保留，操作不删除曲库 Track、歌单、队列或音频文件。
- 选中可用结果播放、暂停、恢复、Stop、Seek、切换本地歌曲再切回在线歌曲。记录请求解析后 FFmpeg 是否使用必要的请求头；不要把完整 URL、Cookie 或鉴权头写进公开报告。
- 无音源、权限限制、试听、失效 URL、网络中断时应显示实际结果，并保持 UI 响应。播放 URL 不应作为稳定歌曲身份或持久曲库路径。
- 在线歌曲加入队列、收藏和自建歌单后重启，确认保存的是平台与歌曲身份；真正播放时重新解析媒体地址。
- 如果有歌词或封面，确认切歌后内容跟随当前歌曲；无歌词、无封面、损坏图片使用空态或默认封面，不显示前一首残留。
- 不以成功 HTTP 状态作为可听证据：真实音频解码、输出设备、持续位置变化和人工听感分别验证。

## 本地功能与界面回归

沿用 `MANUAL-ACCEPTANCE-v1.0.0.md` 的导入、去重、收藏、最近播放、歌单、队列、默认封面、Seek 与响应式布局检查；本次重点覆盖：

- 纯本地曲库不含假歌曲；搜索、排序、多选移除、取消喜欢与清历史只影响对应数据，不删除磁盘音频。
- 播放中和暂停时点击、拖动进度条均可提交；暂停 Seek 后保持暂停；Stop 后重新播放从头开始。
- 四种播放队列模式、连续快速切歌、在线与本地混合队列、自动下一首，不重叠输出也不留上一首音频。
- 860×600、1000×700 与 1200×800 窗口，100%、150%、200% DPI 下检查导航、歌曲行、播放栏、在线状态和错误文本。
- 1000/2000 条曲库及大量在线结果滚动时，不同步解码整批封面或频繁整页重建；观察 UI 响应并记录实际情况。
- 快捷键输入框防抢键、默认封面缩放、播放/暂停按钮动作、创作者署名、设置版本与 Windows EXE 图标。

## 发布文件检查

`runtime-manifest.json` 应与应用 `1.1.0`、EXE 文件版本 `1.1.0.0` 和产品版本 `1.1.0` 一致。逐文件比较 SHA-256，重点确认 `music-gateway/node/node.exe`、完整 Node LICENSE、网关源码、锁文件和 SDK 许可证。

Release 包不含 `Avalonia.Diagnostics`、测试音频、SDK 测试夹具、用户数据库、日志、`.env`、Cookie 或凭据。SDK 源码中的空参数与固定公开请求字段不能单独视为用户凭据；应通过来源与实际内容确认。验证报告保留在 `artifacts/test-reports`，不进入用户发布运行目录。
