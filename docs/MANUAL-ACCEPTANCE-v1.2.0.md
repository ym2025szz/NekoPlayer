# v1.2.0 验收记录

验证数据位于项目的隔离 `artifacts` 目录。真实解码循环使用程序生成的 WAV、内存音频输出和本机 HTTP 服务器，不打开扬声器、不读写正式账号或用户曲库，也不把这些数据复制进 release 包。

## 已执行的真实解码验证

2026-10-08 执行：

```powershell
dotnet run --project tools/NekoPlayer.LoopVerifier/NekoPlayer.LoopVerifier.csproj -c Release --no-restore -- --iterations 20
```

- 协调器的单曲循环连续完成 20 次真实 FFmpeg 自然 EOF，20 个会话编号均不同。
- 生成音频每轮长 6.4 秒，每轮接收 2,457,600 字节的新 48 kHz 双声道 float32 PCM。内存输出加速消费 PCM，但不使用 Seek 代替 EOF。
- 每次完成时播放位置为 6.4 秒、缓冲为 0、解码已结束；观察到的最大缓冲为 1,920,000 字节，等于容量上限，未溢出。队列中的 B 从未启动。
- 本机 HTTP 模拟 A 首轮完整播放后，重播地址返回 403；一次地址刷新后仍返回 403。地址解析总计 3 次，全部为 A，最终保留 A 的错误状态，没有开始 B，也没有额外完成事件。
- 验证最后停止、释放播放器，无取消导致的播放故障；所有验证观察到的 FFmpeg 子进程退出。生成 WAV 在验证结束后删除。

证据：`artifacts/loop-verifier-v1.2.0/loop-verification.json`。输出工厂为 `SilentOutput`，用户数据目录为 `none`。
